# PDF instruction drafts and resumable intake

Instructions are actual uploaded originals. From Checklist, choose **Draft from instructions PDF**, select an inspected PDF, generate proposals and inspect the exact page excerpts. Proposals begin optional. Configure applicability, document combinations and constraints, explain every accepted or rejected proposal, and acknowledge completeness before activation. Manually add missed items. The deterministic extractor is conservative: it matches explicit upload/submit/provide obligations; it cannot prove completeness or automatically interpret every conditional clause. OCR uncertainty, unreadable pages and truncation remain visible.

Drafts retain the original document ID, SHA-256, page number and exact character span. Confirmation records the account owner, timestamp, decisions and edited requirements. Confirmed drafts survive later drafting; deletion of the original cascades its drafts and invalidates the active source-dependent checklist. Old reports remain historical unless document deletion removes dependent records. This is applicant confirmation, not independent institutional certification.

The browser sends original bytes in chunks up to 512 KiB. Sessions persist for 24 hours in SQLite, including the saved offset and checksum. A folder is created only when the whole original has been received, verified and accepted. Re-select the same original after a connection interruption, pause or reload to continue from the last acknowledged chunk. The browser caches only the account-scoped session reference, filename and checksum; file bytes are not stored in browser storage. Repeated finalization returns the saved result without duplicating files or folders. Existing multipart API clients remain supported.

Sessions enforce ownership, CSRF, expiry, inclusive original service limits, ten pending uploads and a 30 MB reservation budget per account. Chunk offsets and final checksums are verified. Partial sessions do not become documents. Account/folder/original erasure cascades session data. Hourly cleanup and startup cleanup remove expired sessions. Session bytes are included in the encrypted metadata backup. Deployment must preserve the private SQLite directory across restarts; a lost server disk cannot be reconstructed from the browser reference.
